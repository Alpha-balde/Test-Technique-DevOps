# Module `container-app-postgres`

Deploys a containerized web application on **Azure Container Apps** with a private
**PostgreSQL Flexible Server**, its network and its secrets (Key Vault).

```hcl
module "app" {
  source          = "../../modules/container-app-postgres"
  project_name    = "deployreq"
  environment     = "staging"
  location        = "francecentral"
  container_image = "ghcr.io/org/app:sha-1234567"
}
```

Required inputs: `project_name`, `environment`, `location`, `container_image` (pinned tag or digest,
`:latest` refused). Every other input has a default (see `variables.tf`).

Main outputs: `app_url`, `health_url`; references to secrets are marked `sensitive`.

## Secrets and write-only arguments

The database password is generated by an ephemeral `random_password`, written to Key Vault
(`db-password`) and read back from Key Vault to configure PostgreSQL and the
`db-connection-string` secret. All of them use **write-only** arguments (`*_wo`): no secret
value is ever stored in the Terraform plan or state.

Write-only values are sent to Azure **only when `db_password_version` changes**.
Increment `db_password_version` when you:

| Change | Why |
|---|---|
| Rotate the database password | A new password is generated, stored in Key Vault and applied to the server. |
| Change `db_name` | The connection string secret must be rewritten. |
| Change `db_admin_login` | The server is recreated and the connection string must use the new login. |
| Change the connection string format (`secrets.tf`: SSL mode, timeout, port…) | The secret is not rewritten otherwise. |

The Container App references the secret by its **version-less** URL, so a new secret version is
picked up without redeploying (Container Apps refreshes Key Vault references periodically; restart
the revision to apply it immediately).

## Requirements

- Terraform >= 1.11, AzureRM >= 5.14.
- The identity running Terraform needs `Owner` (or `Contributor` + `User Access Administrator`)
  on the subscription: it creates role assignments on the Key Vault.
- The resource providers `Microsoft.App`, `Microsoft.DBforPostgreSQL`, `Microsoft.KeyVault`,
  `Microsoft.ManagedIdentity` and `Microsoft.Network` must be registered (the `staging` root
  registers them through the provider configuration).
